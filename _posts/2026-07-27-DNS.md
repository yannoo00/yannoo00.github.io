DNS(domain name system)은 서버들의 계층구조로구현된 분산 데이터베이스이고, 호스트가 분산 데이터베이스로 질의하도록 허락하는 애플리케이션 계층 프로토콜이다.  
DNS 서버는 주로 BIND(Berkeley Internet Name Domain) 소프트웨어를 수행하는 유닉스 컴퓨터다. DSN 프로토콜은 UDP상에서 수행되고 포트번호 53을 이용한다.  

여기서 BIND 소프트웨어란, 널리 쓰이는 표준 DNS 서버용 프로그램으로 도메인 네임을 IP 주소로 변환해주는 시스템이다. 도메인 네임을 주면 IP를 뱉는 프로그램? 그냥 map<string, string> 한 줄로 끝날 것 같지만, 인터넷의 모든 도메인을 하나의 서버에 저장하는건 당연히 불가능하고, 그렇기에 DNS는 분산 데이터베이스이다.  BIND는 이 트리 구조의 분산 데이터베이스에서 탐색 과정을 수행한다.

DNS 서버 계층 구조는 주로 세 가지 계층으로 나눠볼 수 있다.  
- 루트 DNS 서버: 전세계에 13개 루트 서버의 인스턴스 약 1000여개가 나뉘어져 있음  
- 최상위 레벨 도메인(TLD) 서버:  com, org, edu 같은 상위레벨 도메인과, kr, jp 같은 국가의 상위 레벨 도메인에 대한 TLD서버가 있다. TLD 서버는 책임 DNS 서버에 대한 IP 주소를 제공한다.  
- 책임 DNS 서버: 대부분의 대학, 큰 기업들은 자신의 기본 책임 DNS 서버와 보조 DNS 서버를 유지/구현한다. 이 서버에는 DNS와 IP가 매핑되어있는 레코드가 저장된다.  

이 계층에서 벗어나지만 주요한 기능을 하는 서버로 로컬 DNS 서버가 있다.  
ISP들이 로컬 DNS 서버를 가지면서 호스트가 ISP에 연결될 때 그 ISP는 로컬 DNS 서버로부터 IP 주소를 호스트에게 제공한다.  

이러한 구조에서 호스트가 도메인 네임에 매핑되는 IP를 요청하는 상황을 생각해보자.  
<img width="1352" height="1180" alt="Image" src="https://github.com/user-attachments/assets/488f2a6d-5701-42aa-810d-c13016ff4469" />  

- 1) 호스트가 로컬 DNS 서버에 질의한다 (ex: gaia.cs.umass.edu 요청)
- 2) 로컬 DNS 서버는 루트 DNS 서버에 질의를 전달한다.
- 3) 루트 DNS는 .edu를 인식하고, edu에 대한 TLS 서버의 IP 주소 목록을 로컬 DNS에게 돌려준다.
- 4) 로컬 DNS 서버는 TLD 서버에 질의 메시지를 보낸다.  
- 5) TLD 서버는 umass.edu를 인식하고 umass.edu의 책임 DNS 서버 IP로 응답한다.
- 6) 로컬 DNS 서버는 책임 서버에 질의 메시지를 보낸다.  
- 7) 책임 서버는 gaia.cs.umass.edu의 IP 주소로 응답한다.
- 8) 호스트가 질의에 대한 IP를 받는다.  

IP를 얻기 위해 총 8번 메시지를 보냈다. 하지만 매번 이런 과정을 거치는 것은 아니다. 이 과정에서 각 DNS 서버가 특정 도메인에 대한 IP 값을 가지고 있다면 어떨까? 예를 들어 로컬 DNS 서버는 호스트가 자주 요청하는 도메인에 대한 IP 값을 이미 들고 있을 수 있다. 이 경우 네트워크 비용을 상당히 아낄 수 있다.  

추가로, 호스트가 로컬 DNS 서버에 도메인의 최종 IP 값을 알아오라고 요청하는 것은 - 재귀적 질의라고 하고, 로컬 DNS 서버와 다른 DNS 서버들이 직접 메시지를 주고 받는 것은 반복적 질의이다.
