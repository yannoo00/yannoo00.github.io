라우팅은 중앙 집중식 라우팅과 분산형 라우팅으로 나눌 수 있다(여러가지 분류 기준이 있지만 이렇게 나누는 것도 한 축이다). 

<br />

중앙 집중형은 - 네트워크 내 모든 라우터간의 비용을 알고 있는 중앙에서 최적 경로를 계산하여 각 라우터에게 알려주는 방식이다. 

분산형은, 각 라우터는 자신과 이웃한 라우터까지의 비용만 알고 있으면서 그것을 이웃 라우터에게 전파하고, 그렇게 얻은 이웃 노드까지의 비용을 토대로 최적 경로로 수렴해가는 방식이다. 

<br />

##### 중앙 집중형 

각 라우터는 중앙에 자신의 링크 상태를 보고한다. 중앙은 이를 토대로 네트워크 전체에 대한 완전한 정보를 갖게 되고 출발지-목적지간 최소 비용을 계산한다. 모든 링크의 상태(=비용)을 알아야 하므로 LS(Link State) 알고리즘이라고도 부른다. 

이 때 반드시 어떤 중앙 서버가 존재해야만 하는 것은 아니다. 논리적인 중앙이 존재하여 계산 후 내려줄 수 도 있지만 -  **SDN(Software Definition Network)** - 각 라우터의 라우팅 구성요소에 모든 상태가 복제되어 계산이 실행될 수도 있다 -  **OSPF(Open Shortest Path First)**. 두 방식에 대해 각각 더 자세히 알아보자. 

<br />

**OPSF**

- 기본적으로 중앙이 없기 때문에, 중앙에 라우터들이 링크 상태를 보고하는게 아니라 자기들끼리 패킷을 주고 받는다. 즉 자신의 링크 상태를 네트워크에 broad cast 한다. 이를 통해 모든 노드는 전체 지도를 갖게 되고 각자가 최적 경로 탐색을 수행해서 어디로 보낼지를 결정한다.
- 근데 아주 큰 네트워크 내에서 모든 라우터에게 broad cast 하면서 링크 상태 지도를 그리는건 불가능하다...
- 그래서 사용하는게 AS(Autonomous System)이다. 이는 네트워크를 AS 단위로 나누고 AS는 자기들만의 라우팅 체계를 사용하게 된다. 전체 네트워크를 고려하는게 아니라, AS 내부에서의 전달만 고려하는 것이다. 

  - AS란 '같은 관리 주체가 운영하는 라우터들의 묶음'이다. 하나의 AS 안에서는 같은 라우팅 프로토콜을 사용한다. 
  - 대개 ISP 하나의 네트워크가 AS이다. 
  - ISP가 아닌 조직도 AS를 받을 수 있다. (대학, 기업, 콘텐츠 사업자 등.. )
  - 이는 관리 주체끼리 서로의 AS가 운영되는 방식을 숨길 수 있고, 자율적으로 관리할 수 있게 해준다. 또한 서로의 망의 장애가 다른 망에 영향을 끼치 않게 할 수도 있다.
- 그럼 이 AS 끼리는 또 어떻게 통신할 것인가? 그건 BGP(Broader Gateway Protocol)가 맡는다. 

<br />

**SDN**

- 논리적으로 중앙화된 컨트롤러가 있다. 라우터(스위치)들은 자기들끼리 링크 상태를 브로드캐스트하지 않고, 자신의 상태를 컨트롤러에 보고한다.
- 컨트롤러만 네트워크 전체 지도를 가지고, 컨트롤러가 모든 스위치의 경로를 대신 계산해서 각 스위치에 내려준다. 스위치는 받은 대로 패킷을 전달만 한다.
  - 즉 제어 평면(경로 계산)과 데이터 평면(패킷 전달)이 분리된다. 기존 라우터는 둘 다 직접 했다면, SDN 스위치는 데이터 평면만 담당한다.
- 그럼 스위치는 컨트롤러가 내려준 걸 어떻게 사용하나? 플로우 테이블에 저장해 두고 매치 + 액션 방식으로 처리한다.
  - 매치(match): 들어온 패킷의 헤더 필드를 테이블 항목과 비교한다. 목적지 IP만 보는 게 아니라 출발지/목적지 IP, MAC 주소, 포트 번호, 프로토콜 등 여러 계층의 헤더 필드를 볼 수 있다. (플로우 기반 포워딩)
  - 액션(action): 매치되면 특정 포트로 전달 / 폐기 / 헤더 필드 수정 등을 수행한다.
  - 이 방식 하나로 라우터, 방화벽, NAT, 부하 분산기 같은 여러 장비의 역할을 표현할 수 있다.
- 컨트롤러는 어떻게 구성되나?
  - top: 네트워크 제어 애플리케이션 (라우팅, 접근 제어, 부하 분산 등). 다익스트라 같은 경로 계산도 여기서 하나의 애플리케이션으로 동작한다.
  - middle: SDN 컨트롤러 (네트워크 운영체제). 네트워크 전역 상태(링크, 스위치, 호스트 정보)를 관리한다.
  - bottom: 데이터 평면 스위치들
- 결국 네트워크 기능을 소프트웨어로 프로그래밍할 수 있게 된다. 새 기능이 필요하면 장비를 바꾸는 게 아니라 애플리케이션을 추가하면 된다.
- 예: 링크가 끊기면?
  - 스위치가 컨트롤러에 알림 → 컨트롤러가 전역 지도 갱신 → 라우팅 애플리케이션이 새 경로 계산 → 컨트롤러가 영향받는 스위치들의 플로우 테이블 수정
  - OSPF라면 라우터들이 서로 브로드캐스트하고 각자 다시 계산했을 것을, SDN은 컨트롤러가 한 번에 처리한다.
- 그럼 컨트롤러가 죽으면 네트워크 전체가 멈추는 거 아닌가? 
  - 그래서 컨트롤러는 "논리적으로"만 중앙이다. 밖에서 보면 하나처럼 동작하지만, 실제로는 확장성과 장애 대비를 위해 여러 서버에 물리적으로 분산되어 있다.
  - 그래도 컨트롤러 자체의 보안 리스크는 SDN의 단점이다.
